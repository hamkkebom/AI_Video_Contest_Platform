## D-001 · 목업 우선 개발 (2026-02-17)

- **배경**: 색상/레이아웃/역할 구조에 대한 클라이언트 검증이 필요했다.
- **결정**: 실데이터 없이 42페이지 인터랙티브 목업(v3)을 먼저 완성하고, 색상 시안 3종 중 Color C(Warm Earth)를 확정.
- **결과**: 목업이 그대로 실서비스의 뼈대가 됨. 산출물: [archive/MOCKUP_COMPLETION_SUMMARY.md](archive/MOCKUP_COMPLETION_SUMMARY.md)

## D-002 · 범용 SaaS → 단일 공모전 선집중 피벗 (2026-02-23)

- **배경**: 원 기획은 멀티테넌트 공모전 SaaS + 함께봄 생태계 허브. 그러나 "제1회 꿈꾸는 아리랑 AI 영상 공모전"(헐버트 아리랑 채보 130주년, 상금 1,300만원)이라는 실제 운영 기회가 확정됨.
- **결정**: 범용 플랫폼 완성보다 아리랑 공모전 실운영을 우선한다. 브랜드를 kkumple(꿈플)로 리네임하고 전용 랜딩을 만든다. (커밋 `af3fd8a`)
- **결과**: 3~4월 253커밋이 실운영 준비·안정화에 투입. 코어는 실전 검증됐고, 수익화 축은 전부 동결 (→ D-005). 원 기획으로의 회귀(SaaS화)는 [ROADMAP.md](ROADMAP.md) 후보 C로 남음.

## D-003 · 영상 인프라 Mux → Cloudflare Stream 교체 (2026-02~03)

- **배경**: PRD 제약사항에는 "Next.js 15, Supabase, **Mux** (변경 불가)"로 명시돼 있었다.
- **결정**: Mux 대신 Cloudflare Stream을 채택. (커밋 2026-02-23 "feat: add Supabase auth, Cloudflare Stream integration")
- **결과**: `lib/cloudflare-stream.ts` 중심의 업로드/재생 파이프라인으로 운영. "변경 불가" 제약도 상황에 따라 뒤집힐 수 있음을 보여준 사례 — 제약은 문서가 아니라 근거와 함께 관리해야 한다.

## D-004 · 기획 문서 25종 전량 삭제 (2026-03-05)

- **배경**: 2026-02-19에 작성한 정식 문서 체계(사업/기획/디자인/기술/관리/테스트/운영, HTML 25종)가 D-002 피벗과 D-003 교체로 실물과 빠르게 어긋남.
- **결정**: "obsolete"로 판단해 전량 삭제. (커밋 `85c155c`)
- **결과**: 실물과 어긋난 문서는 없앴지만, **목표·의도까지 함께 유실**됨 — 이후 4개월간 프로젝트의 "왜"는 git 히스토리에만 존재. 2026-07-30 문서 재구축(D-008)의 직접적 원인. 교훈: 문서를 버릴 땐 유효한 의도만이라도 승계처를 만들 것.

## D-005 · 수익화 동결 (2026-03, 운영 중 암묵 결정)

- **배경**: BM 설계(구독 3플랜, 대행 수수료)가 있었으나 아리랑 공모전은 무료 참여 구조였고 운영 안정화가 급선무였다.
- **결정**: 결제 연동을 하지 않고 가격표 페이지에 "서비스 준비 중"을 노출. `pricing_plans`/`DEFAULT_FEATURE_ACCESS` 골격은 유지.
- **결과**: 명시적 재개 트리거 없이 방치되던 것을 [ROADMAP.md](ROADMAP.md)의 "의도적 보류" 표로 공식화함.
